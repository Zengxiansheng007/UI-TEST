# UI-TEST 项目测试资产与探索经验复用

版本 1.0，文档待审阅。需求依据为用户确认的 S2 和 A1 六项选择。使用者是维护项目资产的人、执行 UI 测试的 Codex 及接收结果的开发对话。

## 目标和场景

同一项目换一个对话或从新进程启动，仍可从项目入口和源用例找到并执行既有资产。报告能说明用了哪个版本、实际执行到哪一步以及本次业务断言的结果。例如，执行前登录失效时，已选组件应显示为“已选未执行”，并记录原因。

## 首期验收与范围

1. **真实复用。** 在 TodoMVC 添加并完成本轮命名的待办，核对目标已勾选、剩余数 1→0。B 自行重写脚本时只计新探索。声称复用既有版本，须有 B 的实际调用和 A 的读回记录。
2. **无缓存恢复。** 新进程仅凭正式文件找回相同版本及其依赖、暂停范围，并实际调用。
3. **修复后再次复用。** 在隔离项目副本通过公开站正常 UI 准备两行，使旧定位在点击前暴露歧义。限定到目标行，核对只有指定项勾选、剩余数 2→1，再由正常入口实际调用新版。

原项目坐标点击、Ant Design 隐藏副本过滤和按 label 定位作为经验建模样例，其特定页面实测延期。实际运行结果由开发测试提供。测试接入点、既有测试依据和完整验收条件见[实施规格](../specs/ui-test-asset-reuse.md)与 [GitHub 规格 #12](https://github.com/Zengxiansheng007/UI-TEST/issues/12)。
