# UI-Test 契约对齐与 POC 简化需求

- 版本：1.0
- 日期：2026-11-18
- 文档状态：待确认
- 目标项目：UI-TEST 本地仓库中的 ui-test 主 Skill 及相关子 Skill；后续验证通过后同步安装副本。
- 决策基线：访谈 Q001–Q010、永久决定 D001–D011、最终汇总 S1。
- 汇总确认依据：2026-11-18，用户在本聊天展示 S1 后回复“确认”。
- 当前文档版本确认：待用户审阅；汇总确认不代表已确认此文档表达，也不代表实现或测试通过。

## 目标与背景

当前主入口与部分子 Skill 的运行契约不同步，导致合法的新结果或任务包可能被拒绝、交接信息丢失、模块就绪判断不一致。另有运行目录与发布登记门槛增加 POC 使用成本。

本次目标是在保留真实结果和必要业务检查的前提下，打通主/子 Skill 的 UI 自动化链路。以可观察的页面操作、业务断言、网络监听证据和报告一致性验证效果；不以统一版本字符串代替字段和行为对齐。

现状依据为 2026-11-17/18 对已安装源码的静态审计及研究。它证明存在契约矛盾，不证明真实业务链已执行失败，也不代表修复已完成。

## 使用者与场景

- 使用者让 Codex 执行已授权的 UI 用例，期望不因无关的目录或发布登记被阻断。
- 用例维护者需要一个连续用例完成多个明确阶段，得到每阶段的真实结果，避免超时后重复提交。
- 开发维护者需要主 Packet、checkpoint、交接、验证、证据和报告使用一致契约，并能在仓库审查、验证和回滚改动。

## 范围

包含六组已确认冲突、同一根因的必要生产者/消费者/文档/样例/测试更新、POC 启动门槛简化、全链路网络只监听，以及仓库开发后备份同步安装。

范围以 ui-test、九个活跃子 Skill 及其直接依赖为边界。四个归档兼容入口的名称并存本身不属于缺陷，仅在实际指向或调用受本次改动影响时调整。不修改无关 Skill 或其它项目。

明确不做：

- 从 v2 重新生成报告；旧运行产物自动转换后续跑；新增历史迁移工具。
- 额外简化 V5 结果持久化、提交回执和验收证据链。
- 由 ui-test 额外调用、重放接口，或主动 API 轮询补证。
- 新增 POC/正式双轨治理框架、机器码授权或逐阶段/逐请求人工审批。
- 本轮 GitHub 提交/推送、工单发布、真实业务站点操作或外部模型调用。

已有报告、执行证据和失败记录保留原样。源用例与可复用定义可用于生成新产物；历史运行身份和已过期的就绪结论不能继承为本次成功。

## 正常、失败与边界行为

### 正常流程

源用例与当前任务形成新主 Packet；执行产生带完整身份的 checkpoint 快照；需要交接时使用主 Packet 内的交接信息。模块就绪校验通过后继续已授权 UI 步骤，监听自然网络请求；每个写入阶段按前置与后置断言推进，最终形成真实 V5 结果、证据和报告。

这是能力及契约关系的说明，不要求每个用例固定经过所有可选子 Skill。

### 模块就绪与网络证据

目标页面、当前登录会话、运行归属和有效期正确，是两种证据组合的共同前提。重复同一个 UI 特征不算两个独立特征；无关请求、旧会话响应、业务失败响应或只有 HTTP 200 均不足以证明就绪。

GET/POST 方法名称本身不决定业务成功。已授权页面自然发出的 POST 查询可以被观察；这不授予工具额外发送或重放 POST 的权限。监听不修改请求/响应制造通过，证据仅保留必要的脱敏内容。

示例（假设）：打开公告列表后，页面自然发出列表查询；标题匹配，响应也符合该模块业务成功条件，即可组成“一 UI＋HTTP”证据。若目标请求没有出现，使用两个有效 UI 特征或如实报告证据不足，不主动调用接口补证。

### 多阶段与未知结果

完整流程已获得明确授权后，各阶段不再重复请求人工确认。阶段声明不授予额外业务权限，也不能临时创建阶段来绕过次数限制。

示例（假设）：“创建草稿→修改草稿”允许两个已声明阶段分别保存一次。首次保存超时且结果未知时，保留未知结果，禁止盲目再次保存或进入依赖首次成功的修改阶段。

### 旧产物、缺字段与失败报告

旧文件保留，重新生成不覆盖历史证据。新输入缺少必要身份、字段冲突或使用未知版本时，给出可定位的错误。失败结果可以如实出现在 V5 报告中，不能因报告生成成功而变成测试成功。

结果或证据关联不完整时如实表达，不将节点业务通过升级为整体完成或外部人工验收通过。保留的 V5 结果链仍须满足其真实关联要求。

## 质量约束与实施边界

- 正式需求与验收编号保持稳定；发现必须改变业务决定时，回到对应访谈问题，不静默改变范围。
- 主契约只有一个权威来源，相关 Skill 的代码、指令、样例和校验共同更新，避免各自复制不一致规则。
- 先做针对性及跨 Skill 契约检查，再以可见本地受控页面验证关键 UI 行为；实现产生广泛影响时覆盖必要回归。
- 未承诺新的性能指标、平台兼容范围或真实业务成功率。无法验证的项目须记录原因，不宣称通过。
- 本地源码开发落点为现有 UI-TEST 仓库；安装同步只涉及本次相关 Skill。具体清单、备份位置和命令在实施前基于实际变更准备。
- GitHub 发布和真实站点验收不包含在本次文档确认中。本地页面通过不代表生产行为、PyCharm 人工验收或外部模型效果通过。

## 决策依据与待细化项

主 Packet 统一纳入交接字段和 checkpoint 完整快照，是用户在 Q002/Q003 明确选择的方案；研究阶段提出的独立交接上下文、外部补入当前身份建议未被采纳。理由与取舍保存在 [ADR-0001](../adr/0001-unified-packet-and-checkpoint-snapshots.md)。

POC 取消的是目录和发布资产身份启动资格。限定源码搜索未发现硬件机器码授权实现；本机名称相关代码不能直接等同机器授权，真实内容摘要也不能一律当作待删除防御。

需求层面无未答业务选择。后续规格须固定新契约精确版本、字段布局、缺失历史表达、派生身份/来源关系、有效期参数、真实证据映射和完整写集。这些技术工作不得新增主动接口调用、旧版续跑或重新引入已取消的准入要求；如出现新的业务取舍，再补确认。

剩余限制：尚无实现或测试结果；当前源码目录的下游项目适配依赖须在实施时按准确变更点追踪。不得把静态研究覆盖范围当作已穷尽所有运行调用方。
