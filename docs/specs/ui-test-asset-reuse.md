## Problem Statement

项目里已经有可用的导航、定位器、组件和脚本，也积累了处理坐标、隐藏副本和表单标签的经验。下一次运行经常需要维护者提示文件名或重述做法。现有查询可以返回经验建议，项目运行时也能执行已注册的 Flow，但使用者难以从一次结果知道究竟调用了哪个版本、它是否仍适用，以及一次失败会影响哪些用例。

## Solution

新对话拿到项目入口和源用例，就能发现已有实现，由项目正常 pytest 入口执行适用的已启用版本，并用当前页面验证源用例的业务断言。项目保存可恢复的版本、依赖、经验和启停依据。RunResultV5 关联当次实际使用记录。对确认失效的版本，按影响范围修复并以新的真实调用验证恢复。

## User Stories

1. 作为项目维护者，我希望接入项目时自动识别配置目录里的四类资产，以便忘记文件名也能找到原实现。
2. 作为脚本作者，我希望登记只读取代码和声明，以便扫描历史脚本时不会触发其顶层动作。
3. 作为测试人员，我希望歧义条目带来源和待核对原因，以便查清入口后再执行。
4. 作为探索者，我希望带证据的成功策略和失败模式都能成为候选，以便后来者知道何时适用、何时应避开。
5. 作为项目维护者，我希望资产移动或更新后仍能追溯原版本和调用关系，以便找出受影响的用例。
6. 作为接手任务的 Codex，我希望通过项目文件恢复目录、启停决定及使用记录，以便从全新的进程继续工作。
7. 作为用例作者，我希望先采用显式绑定，再考虑本项目内适用的共享组件，以便同名资产不会选错环境或对象。
8. 作为测试人员，我希望知道冲突和未命中的原因，以便在原授权范围内决定哪些步骤仍可探索。
9. 作为执行任务的 Codex，我希望对输入、动作和副作用明确的旧脚本做薄适配，以便在当前会话复用已验证的逻辑。
10. 作为执行任务的 Codex，我希望能依据独立重跑和原断言，自行批准限定范围的新经验，以便新类型也能沉淀。
11. 作为测试人员，我希望一次用例固定版本且每步检查停用状态，以便并行发布新版时仍能解释当前结果。
12. 作为报告读者，我希望分清发现、选用、进入入口、结果和跳过原因，以便登录失败时能判断后续组件是否实际运行。
13. 作为验收人，我希望能从 V5 追到本次资产、经验和业务断言证据，以便识别重写脚本造成的表面命中。
14. 作为维护者，我希望先判断资产、业务、环境、数据或未知原因，以便只暂停真正失效的版本和范围。
15. 作为组件作者，我希望按直接和传递依赖回归受影响用例并保留旧版，以便修复可以核查、必要时可以恢复。
16. 作为开发对话的接收方，我希望全新对话自行运行并回传可读回的结果，以便确认交付物可以独立复用。
17. 作为测试负责人，我希望提交结果未知时保留现场和已用预算，以便恢复报告或重送消息时不会重复业务写入。

## Implementation Decisions

- **发现与身份（R01、R03）。** 从项目配置、源用例绑定和已有声明开始，只在指定资产目录静态发现导航、定位、组件及脚本。记录稳定 ID、版本、来源、可调用符号、可恢复内容、输入、副作用、适用条件及依赖。识别不清的条目标待核对。内容相同的重扫去重，移动需唯一核对身份和版本，外部修改登记为候选，缺失版本如实记录。
- **正式存储（R02–R04）。** 文件保存资产版本、调用关系、经验、范围内的启停决定及每次运行的使用事件。经验记录条件、动作、预期、实际、来源步骤及脱敏证据。使用文件锁和预期修订检查，先写完整记录再切换清单。并发更新同一决定须基于最新修订重新评估。中断保留完整旧版或新版及未完成尝试。事件以运行、步骤、尝试和序号去重，同键不同内容保留冲突。首版支持查适用版本、反查依赖和追溯运行三种文件查询；测出规模或延迟瓶颈后才考虑可重建的 SQLite 索引。
- **选择与权限（R05–R07）。** 保留项目组、产品、系统、模块、功能、checkpoint、环境和风险八项范围；先核源用例绑定，再核同项目同环境专用、显式共享资产。检查启用范围、前置条件、依赖和当前用例授权。同级冲突不猜选，硬绑定失效要标出受阻步骤。未命中可按原授权探索。证据充分的候选由 Codex 在项目内独立重跑，原断言通过后记录理由、证据和启用范围，包括新类型。未知副作用的历史脚本留待核对。
- **实际执行（R07–R08）。** 复用项目 pytest 节点、项目运行时及 Flow/Page/Component 的实际调用位置。脚本调用子组件时沿用当前 page/context。一次用例固定资产和依赖版本；步骤前发现暂停则停止受影响步骤，中途发布的新版供下次运行使用。原业务断言由源用例维护。
- **证据（R08）。** RunResultV5 引用含运行、用例、步骤、尝试、版本和证据的使用明细。区分查到、选用、进入入口、动作与断言结果或跳过原因。经验命中须能解释采用或排除了哪种策略。仅缺复用明细时，原断言、写预算及 V5 业务证据完整的普通用例可以继续，标记“复用未证实”，专项复用验收不能通过。历史 checkpoint 执行快照只属于原运行。
- **归因与修复（R09–R10）。** 区分资产、业务、环境、数据及未知。确认资产原因才暂停该版本的受影响范围；原因未知停止依赖步骤。自管资产从源头创建可恢复新版，外来或归属不明资产在项目侧适配，生成的薄测试回到源绑定修复。只自动修复目标与原断言不变的低风险问题。反查直接和传递依赖，在受影响用例验证后启用；动态依赖未查清时暂缓扩大范围。保留旧版和失败证据，恢复前版须核对其仍适用、已验证且未暂停。
- **交付（R11）。** 接收端按运行标识核对资产版本、实际调用、断言、结果、证据和失败或跳过原因。通信失败只重送同一回执。同一用例的动作仍受原写预算与凭据保护约束。仅被动观察已授权 UI 自然触发、符合审查条件的请求与响应。禁止额外调用、轮询或重放业务接口，写结果未知时禁止重提。

## Testing Decisions

验收从已确认的项目正常入口观察行为，以本次资产调用、可见业务状态和接收端回执为依据。复用已有 Flow 运行测试、经验范围测试、V5 证据关联与中断恢复测试的做法。文件查询与故障样本用于定位失败；端到端结论由以下公开站场景给出。

| 验收 | 可观察条件 |
|---|---|
| AC-01 跨对话同版复用（R01–R08、R11） | 开发对话 A 在公开 TodoMVC 实跑并沉淀资产。全新对话 B 只得项目入口、源用例或业务目标及回传目标，在独立浏览器上下文用新的运行 ID 自行找到并调用同版资产。B 核对自己创建的待办被勾选、剩余数由 1 到 0。A 实际读回 B 的版本、断言、结果和证据。临时重写脚本只记新探索。 |
| AC-02 无缓存恢复（R01、R03–R05） | 在无缓存的新进程中仅凭正式文件恢复相同的可用版本、依赖和暂停范围，并实际调用同版。重扫不重复登记，外部同名文件不冒用旧身份。 |
| AC-03 失效到新版复用（R09–R11） | 在隔离的公开测试项目副本中通过正常 UI 准备两条待办。旧定位匹配两项，在点击前暴露歧义。保存失败并限定到目标行，原断言核对仅指定项勾选、另一项不变、剩余数从 2 到 1。受影响用例回归后，后续正常运行实际使用新版。 |
| AC-04 选择与启用（R02、R05–R07） | 输入显式绑定、同级冲突、不同环境、未知副作用脚本和未经验证的新经验，检查选用或跳过原因。只有适用范围内、经独立重跑且原断言通过的策略可以自行启用。 |
| AC-05 并发与中断（R03、R04、R08） | 两个运行更新同一决定、运行中另发新版或暂停旧版、清单更新中断、重复投递事件。核对无静默覆盖、无半套可用版本，已暂停步骤停止，同一回执只计一次。 |
| AC-06 失败归因与证据（R07–R10） | 登录过期保留“已选未执行”，共享组件仍可供其他适用运行使用。缺复用明细单列未证实。提交结果未知时，停止依赖步骤，保留已用预算，核对没有额外接口请求或重复提交。 |

## Out of Scope

首期延期验证原项目的项目选择器坐标点击、Ant Design 隐藏副本过滤及按 label 定位的特定页面。这些例子用于经验建模。首版数据库加速、跨项目自动推广、生产业务操作及变更原业务断言均在本规格范围之外。
