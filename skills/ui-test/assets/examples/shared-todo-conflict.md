# 共享待办并发冲突场景

下例为合成共享待办系统的编写前练习。演示用证据摘要如下。公开 TodoMVC 演示页的独立浏览器上下文使用各自本地存储，不能作为跨会话共享的实测证据。

| 证据引用 | 已有观察或断言 |
|---|---|
| visible:A.2 | A 在团队清单中将编号 42 的“核对库存”标为完成。 |
| visible:B.1 | B 读取同一团队清单、编号 42 的状态。 |
| case:B.step3 | B 的业务断言要求此行显示“待处理”。 |
| case:C.step2 | C 核对独立帮助页面的标题。 |

两端是 `test_todo.py::test_complete[team]` 和 `test_todo.py::test_pending[team]`。对象为 `demo/team/todo/42`。A 写“完成”，B 读“状态”并断言“待处理”；A 先完成时 B 会看到“已完成”。证据为 visible:A.2、visible:B.1、case:B.step3。

| 示例指令（虚构消息） | 作者或主任务的处理 |
|---|---|
| m1「把 A、B 写成正式脚本，尽快跑完。」 | 给出上述风险，编写两例，运行依次收尾，无须问询。 |
| m2「并发跑 A、B、C。」 | 只问“A 完成 42 后，B 的待处理断言可能失败，仍要并发这两例吗？”已授权且独立的 C 可以先行。 |
| m3「接受本批 A 完成 42 导致 B 的待处理断言失败的风险，继续并发。」 | 保存当前 task_ref、batch_ref、A/B/C 精确 nodeids、上述冲突及 instruction_ref=m3。继续同一批时直接复用。 |
| 下一批加入 D、改用待办 43，或 A 现在删除 42 | 重新核对范围、对象及受影响断言，仅询问仍影响本次并发的具体冲突。 |
| 只选各自独立上下文中的本地 TodoMVC 用例 | 已有证据显示状态隔离时直接编写；执行仍遵从本次调度指令。 |
